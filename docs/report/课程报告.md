## 一、复现目标

多智能体系统中，一个智能体的中间输出会成为其他智能体的输入。局部的计算错误、事实冲突或遗漏条件可能沿通信边扩散，并在多轮讨论中被重复引用。AgentDropoutV2 在消息进入下游之前检查其质量：对能够修正的错误提供反馈，对多次修正仍不合格的消息停止传播，从而控制错误信息在团队中的累积。[1]

论文的核心贡献是将失败轨迹转化为可复用的错误指标，依据当前任务和角色检索相关指标，并将逐项审计与“反馈修正或拒绝”结合。它控制的是某一次消息是否传播，保留智能体在后续轮次继续产生新消息的能力。

本组完成部分复现与框架适配。复现部分选取 GSM8K 和 MATH500 两个数学基准，回收完整主实验记录并按原运行评分字段复算，与论文 v1 的对应指标对照。适配部分在 LycheeMAS 的接口上接入固定指标 ADv2，并将 MASPO 提示词优化、五 Agent 两轮推理和最终汇总串成可执行流程。目标是验证模块能够在框架内调用、消息流符合设定、结果与审计轨迹能够复查。

## 二、方法描述

### 2.1 论文机制

离线阶段先运行多智能体系统，收集失败轨迹，从其中归纳具有具体触发条件和检查目标的错误指标，并完成清洗与去重。在线阶段根据任务、角色和当前可见上下文选择适用指标，由审核模型检查当前草稿。通过的消息进入正常通信；不通过时，将违规项和反馈送回原角色重生成，直到通过或达到重试上限。论文还提供全局回退，使有效信息不足时仍能继续求解。

固定指标适配保留在线的审计、反馈和阻断结构。指标记录 id、description 和 keywords；每次审计记录草稿、激活指标、违规项与反馈。控制结果含最终 content、decision、retries 和 attempts。拒绝的 content 为 None，原稿只进入审计文件，不进入后续角色的可见上下文。

| 状态 | 触发条件 | 后续动作 |
| --- | --- | --- |
| Pass | 没有超过阈值的违规项 | 保存通过的最终版本，允许传播 |
| Retry | 有违规项，仍有重生成预算 | 原角色结合具体反馈重新生成并再次审核 |
| Reject | 重试预算耗尽仍未通过 | 阻断该次消息；保留草稿和理由供审计 |

### 2.2 MASPO 与两轮团队

MASPO 在训练划分中的少量问题上改写各角色的提示词，不更新模型权重。候选提示词与当前提示词进行成对评估，分别比较本节点输出、下游输出和最终答案，组合 Local、Lookahead、Global 三类信号；再以坐标式搜索和 beam 保存候选。本次沿用这套优化器，使用同一非思考模型承担执行、比较和提示词提议，搜索深度按小样本可用性实验设置。[2]

团队按 A、B、C、D、E 的顺序执行。A 与 E 是数学求解者，B 分析条件与数量关系，C 负责程序化计算，D 检查前面的推理。A 与 E 共用角色类型，但节点和提示词各自独立，因此是五 Agent、四种角色。选择题中，C 改为逐项核对选项证据。数学任务中，C 的赋值式 Python 由受限 AST 算术解释器实际求值，只开放算术表达式和变量赋值。

优化与正式推理共用两轮执行器。角色提示词在两轮中共享，改变某个角色的提示词后，重新计算受影响节点及其后继，包含第二轮中的同一角色。优化阶段评估团队输出；测试阶段加载保存的提示词，再在消息出口启用 ADv2。训练问题用于选择提示词，测试问题只用于最终执行和评分。

### 2.3 实现参数与差异

集成配置设置 max_retries=1，即初稿之后最多重生成一次，最多审核两版；violation_threshold=0，表示激活指标中出现违规项就不能放行。判官返回结构为 violations 和 feedback；格式错误、未知指标及调用异常进入错误记录。非思考模式通过请求参数 enable_thinking=false 固定。

论文主实验复现采用归档中的原始代码、提示词和评分结果，其配置差异在第四节逐项列明。LycheeMAS 适配采用人工固定指标，替代失败轨迹建池与语义检索；在本次任务上直接挂载全局适用的指标。所有角色都读取完整的已通过消息，便于跨数学与选择题复用；这也避免把拒绝消息转换成数字 0。该接口版本不执行论文的全局回退，final 被拒绝或模型调用失败时将该题记入失败分母。

本次集成实验使用 Linux、Python 3.10.19、LangGraph 1.2.20 与 SymPy 1.14.0。模型服务为 vLLM 0.19.1，在一张 A100-SXM4-40GB 上加载 Qwen3-8B，上下文上限 16,384 token、最大服务序列数 16。执行、提示词提议、比较和审核均使用这一模型并关闭思考；客户端按题并发 8。角色生成在优化阶段上限为 1,024 token，测试阶段 MATH 为 2,048，其余为 1,024；各 benchmark 依次运行。

## 三、适配逻辑

### 3.1 框架现状与接入位置

LycheeMAS v0.3 以 AgentSpec 保存节点角色、system_prompt 和 predecessors，以注册器按方法名选择实现，提供构建、运行前、记忆、执行和运行后五类接口。接口声明与算法实现分别放在 plugins/ 和 methods/，执行端通过异步回调调用模型。已有模块为本次适配提供了图结构、提示词写回与运行时控制的基础。

| 接口或扩展点 | 原有能力 | 本次使用或补充 |
| --- | --- | --- |
| build_langgraph<br>AgentSpec / GraphView | 静态团队、前驱关系和节点元数据 | 构造五 Agent 的两轮展开图，保存角色提示词映射 |
| optimize_langgraph<br>MASPOOptimizer | 提示词 optimize / apply；多粒度比较与搜索 | 共用两轮执行器评估候选；产物加载回测试团队 |
| 指标配置与运行器 | 实践分支已有运行前配置与运行时控制的分层 | 课程 CLI 装载固定指标和重试参数，直接构造控制器 |
| runtime_controller<br>AgentDropoutV2Controller | 逐消息 Pass / Retry / Reject | 在每个角色和 final 的出口执行门控 |
| attach_memory<br>运行后优化接口 | 协议与注册入口；部分算法仍为显式占位 | 使用本任务的轮次状态；审计轨迹可作为后续模块输入 |

原框架中的接口存在不等于具体算法已完成。所检查的 v0.3 源码中，attach_memory 的节点注入入口仍会抛出 NotImplementedError；运行后归因、信用分配与部分训练方法也保留显式占位。本次独立仓库只保留必要的类型、注册器、GraphView、MASPO 和 ADv2 模块，再增加课程运行层。它管理任务内的本轮及上一轮状态，不依赖这些尚未接通的组件。

### 3.2 数据与调用流程

数据加载器读取指定数据集的训练划分和测试划分，固定种子抽样并保存题目 ID。训练问题进入 MASPO，得到角色到提示词的映射文件。测试时加载这份映射，为每道题建立独立执行状态。每个节点先构造允许看见的上下文，再生成、审计、必要时修正，最后把通过的结果写回状态。

同一轮中，角色 i 可以读取位于它之前的角色 j<i；第二轮另可读取上一轮中 j≤i 的角色。表中列出的都是通过审核后的最终版本；被拒绝的位置直接省略。

| 接收者 | 同轮可见 | 第二轮另可见的上一轮消息 |
| --- | --- | --- |
| A | 无 | A |
| B | A | A、B |
| C | A、B | A、B、C |
| D | A、B、C | A、B、C、D |
| E | A、B、C、D | A、B、C、D、E |

例如，第一轮 B 的初稿被判定计算有误，重生成后通过，则第一轮 C、D、E 及第二轮 B、C、D、E 读取的都是 B 的修正版；如果 B 最终被拒绝，这些接收者均看不到该消息。第二轮 A 仍然只读取上一轮 A。第二轮结束后，final 汇总该轮所有通过的输出，并接受同样的审核。

调用链为：训练问题 → MASPO 生成与比较候选 → 保存角色提示词 → 测试问题 → A₁…E₁ → A₂…E₂ → final → 答案解析与评分。每个角色出口都包含“审计 → 放行 / 反馈重试 / 阻断”。gold 保存在评分对象中，不进入角色生成或 ADv2 判官请求。不同题之间并发，同一题内保持设定顺序。

### 3.3 代码改动与主要问题

新仓库将所需 LycheeMAS 核心模块作为独立子集保留。主要修改 MASPO 的执行器注入和角色共享映射；新增 course 运行层，负责两轮图、固定指标、数据抽样、模型接口和评分。ADv2 控制器由 CLI 装载固定指标后构造，CourseExecutor 在消息出口调用 process。选择 LangGraph 载体时，展开图注册 AgentSpec metadata 并经 compile().ainvoke() 执行。

| 文件或模块 | 变更 | 作用 |
| --- | --- | --- |
| course/workflow.py | 新增 | 两轮通信、共享提示词、消息门控、算术工具与图执行 |
| course/cli.py | 新增 | 优化与测试流程、并发、恢复、全分母汇总 |
| course/io.py、data.py | 新增 | 非思考 HTTP 调用、逐题数据与评分 |
| methods/prerun/maspo/ | 修改 | 保留多粒度比较与搜索，注入两轮执行器 |
| methods/runtime/<br>agentdropout_v2.py | 复用 | 严格审计、有限重生成和拒绝控制 |
| tests/test_course.py | 新增 | 通信隔离、提示词共享、工具、解析与恢复检查 |

第一处问题是优化与执行的一致性及拒绝消息隔离。单轮执行器会使候选提示词的评价流程与最终两轮运行不同；空输出进入旧数字提取逻辑又可能变为默认值 0。为此，MASPO 候选评估与最终运行共用 CourseExecutor，两轮对应节点绑定同一角色提示词；上下文仅由 accepted 状态构造，拒绝输出保持 None。候选变化沿实际时空连接传播，下游、跨轮缓存与 final 复用同一过滤规则，并由测试检查拒绝稿和修正前旧稿不进入后续提示词。

第二处问题是模型输出预算与完整性：MATH 首次提示词提议达到 1,536 token 上限而中止；增加独立提议预算至 3,072 后完成优化。随后测试出现 1,024 token 截断，因此复用已完成的提示词，以 2,048 token 统一重跑全部 20 题。对仍未完整结束的文本或 JSON，客户端最多追加两次简短格式重试；重试不加入标准答案，失败响应和成本全部保留。

## 四、测试结果

### 4.1 论文主实验复算

复现结果来自从原实验服务器迁移保留的完整主运行。按同一次主配置读取逐题评分字段，对 GSM8K 的 1,319 题和 MATH500 的 500 题分别计数，不跨运行拼题。两项结果属于已完成的历史主实验，本次完成了记录回收、配置核对和重新聚合。

| 基准 | 论文 v1 | 本组主运行 | 差值 |
| --- | --- | --- | --- |
| GSM8K | 91.74% | 1209 / 1319 = 91.66% | −0.08 个百分点 |
| MATH500 | 78.40% | 398 / 500 = 79.60% | +1.20 个百分点 |

执行模型均为 Qwen3-8B。论文 v1 使用 GPT-4.1-mini 选择器、直接选择 top-5 指标与 pass 阈值 100%；归档主配置使用 Qwen3.5-9B 选择器、rerank top-20 后选择 1–5 项与 pass 阈值 60%。因此，两项结果达到论文对应基准的相近水平，但数值差异同时受到选择器、指标选择及阈值设置的影响。归档中的九月论文快照记录 91.66% 与 79.60%，与此次重新聚合一致。

### 4.2 组合适配可用性

本次实验为每个 benchmark 使用 4 道训练划分问题优化提示词，再执行预先抽取的 20 道测试题。GSM8K 使用官方 train/test；MATH 使用原始 7500 题训练集与 MATH500 测试集；ARC-Easy 与 OpenBookQA 使用官方训练和测试划分。先固定抽出 8 道训练候选题，再从中选 4 道用于优化；各次抽样种子均为 42，实际题号保存在 selection.json。测试题与优化题的 ID 和规范化题面均不重叠。四项测试均以 LangGraph 编译执行。

| 数据集 | 优化题数 | 测试题数 | 完成 / 正确 | 审计行为 |
| --- | --- | --- | --- | --- |
| GSM8K | 4 | 20 | 20 完成 / 16 正确<br>80% | 重试 2；阻断 2<br>修订后通过 0 |
| MATH500 | 4 | 20 | 20 完成 / 15 正确<br>75% | 重试 11；阻断 5<br>修订后通过 6 |
| ARC-Easy | 4 | 20 | 20 完成 / 18 正确<br>90% | 重试 14；阻断 11<br>修订后通过 3 |
| OpenBookQA | 4 | 20 | 20 完成 / 19 正确<br>95% | 重试 35；阻断 27<br>修订后通过 8 |

最终题目结果中记录 62 次反馈重试，其中 17 条消息在修订后通过，45 条消息最终被阻断。GSM8K 的提示词变化角色为 E；MATH500 的提示词变化角色为 C；ARC-Easy 的提示词变化角色为 D；OpenBookQA 保留初始提示词。优化后提示词通过实际运行快照与角色输出记录确认已加载。

MATH 最终 20 题按统一数学等价规则离线重评分。题 279 的模型输出为 7π，标准答案为 7\pi；将 Unicode π 与 LaTeX π 归一后，该题从格式误判修正为正确，最终为 15/20。原模型输出不变，旧评分与逐题变更保存在 rescore_audit.json，可由 rescore_math.py 复算。

GSM8K 测试题 54 提供了一个审核误判实例：A 与第二轮 A 的初稿均正确得到 7+3×7+12=40，但判官把“三倍”的参照对象误解成 12，反馈引导模型改成 55 后再拒绝；团队最终也回答 55。两条消息确实被阻断，说明门控路径生效，同时说明同一 8B 模型的审核判断也可能出错，不能把拒绝次数直接等同于成功拦截错误的次数。

按标准答案复核，ARC-Easy 三条“修订后通过”分别为一条由错改对、一条由对改错、一条保持正确；OpenBookQA 八条中，两条改为标准选项，五条保持标准选项，一条质疑题设后改为非选项文本。MATH 六条中，一条由对改错、两条保持正确、三条仍然错误。因此，“修订后通过”表示判官接受，不能直接解释为答案已修正。

### 4.3 功能测试与结果分析

| 检查内容 | 验证方式 | 结果 |
| --- | --- | --- |
| 确定性工程测试 | 时空前驱、共享提示词、消息隔离、恢复、输出格式、数学等价评分与执行器等价 | 17 项通过 |
| 真实模型控制分支 | 人为构造三组草稿及修订，真实 Qwen3-8B 审核 Pass / Retry→Pass / Retry→Reject | 3/3 通过 |
| 真实服务非思考并发 | 8 个同时请求；检查答案、返回内容和思考字段 | 8/8 通过 |
| 完整组合流程 | MASPO 保存提示词后，由 StateGraph 执行两轮 ADv2 团队 | 见四项实测 |

服务器上的 17 项确定性测试全部通过，其中原生 LangGraph 测试实际调用 compile().ainvoke()，并逐节点比较 GraphView 执行器的输入、输出与审计记录。真实判官分支探针另使用 5 次模型审核覆盖三条控制路径，返回内容均未截断；该探针的草稿和修订文字是预设的。benchmark 运行中的反馈修订由模型实际生成，单独记录在各题 attempts 中。

上述两类测试回答不同问题：历史主运行用于核对论文任务上的准确率；本次小规模测试用于确认提示词优化产物、两轮通信、运行时门控和结果落盘能够连续工作。集成测试保留固定测试子集及完整失败记录，准确率按全部抽样题数计分。运行期间的错误、修正与拒绝均从轨迹统计，不以最终答对替代接口行为检查。

| max_retries / threshold | 1 / 0 | 最多重生成一次，激活指标零容忍 |
| seed / concurrency | 42 / 8 | 固定抽样；不同题并发 |
| max_tokens | 1024 / 2048 | 优化为 1024；MATH 测试为 2048，其余测试为 1024 |
| proposal_max_tokens | 1536 / 3072 | MATH 提议为 3072，其余为 1536；与角色生成预算分离 |
| 格式重试上限 | 2 | 仅对不完整输出追加；与 ADv2 语义反馈重试分开 |

主实验复算脚本逐行读取已保留的原始评分结果，输出分子、分母、准确率和配置说明；独立重复按同样方式读取。集成实验以每题的 task_id 对齐结果和事件，先检查是否正常完成，再查看各角色的通过、重试和拒绝路径，最后核对最终答案与评分。所有题目都保留在统计分母中。
